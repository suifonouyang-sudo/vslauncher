# 常见问题

## 虚拟屏怎么创建（本应用不负责建屏）

本应用**不创建**虚拟屏，请先自行建好：

```bash
adb shell settings put global overlay_display_devices "720x1280/280"
```

多块屏用分号分隔，例如 `"720x1280/280;1280x720/280"`。建好后回到应用的「虚拟屏」页点「刷新」即可看到，
之后在应用列表里点任意应用，就会弹出屏幕列表让你选。

> 若这台设备的 ROM 屏蔽了这个设置项，见下一节。

## 建了虚拟屏，但屏幕上什么都没出现

先确认虚拟屏是真的建起来了。在电脑上执行：

```bash
adb shell dumpsys display | grep -oE "displayId=[0-9]+, uniqueId='[^']*'"
```

正常应该能看到一条 `uniqueId='overlay:1'` 之类的记录，对应的 `displayId` 就是虚拟屏编号。

**如果一条 `overlay:` 都没有**，说明这台设备的 ROM 屏蔽了 AOSP 的开发者选项机制。本应用依赖的
`settings put global overlay_display_devices` 命令会被系统静默忽略，这种情况下无法使用，换设备或刷原生/类原生系统。

**如果有 `overlay:` 记录但屏幕上没画面**，检查是否选错了屏：应用内「虚拟屏」页可以看到屏幕列表和每块屏的
前台应用，用「选中」切换目标屏。

## Shizuku 显示已授权，但所有命令都失败

部分设备的 Shizuku 是第三方 fork（例如 `13.7.0-thedjchi`），其 binder 注册方式与官方版不同，
用 `SystemServiceHelper.getSystemService("shizuku")` 取不到服务，表现为「明明 uid 已经是 2000，
但每条命令都抛异常」。

本项目已经处理了这种情况：拿不到时自动回退到 `Shizuku.getBinder()`。如果仍然失败，请贴出
应用内「日志」页的内容（每条命令和返回码都会记录）。

## 应用启动了，但跑到主屏而不是虚拟屏

`am start --display <id>` 是否生效，取决于目标应用的 `AndroidManifest` 里有没有为 Activity 声明
`android:resizeableActivity="false"` 或限制 `screenOrientation`。这类应用会强制回到默认显示屏。

可以先用命令手动验证一次：

```bash
adb shell dumpsys activity activities | grep -A6 "Display #<id>"
```

如果上面这段里没有目标应用，那就是系统层面拒绝了迁移，本应用无法绕过。

## 悬浮球突然不见了

先看进程还在不在：

```bash
adb shell ps -A | grep vsbox
```

进程没了，多半是被系统或第三方清理工具杀掉了（README 里提到的电池优化白名单可以缓解）：

```bash
adb shell dumpsys activity exit-info com.vsbox.launcher | head -20
```

如果退出原因显示 `USER REQUESTED`，通常是清理类应用按用户配置强杀，不是崩溃。

进程还在但球不见了，检查悬浮窗权限有没有被系统回收：应用内重新勾选一次「显示悬浮球」。

## 怎么把本应用设成默认桌面

应用在 `AndroidManifest` 里注册了 `CATEGORY_HOME`，去系统设置里选择即可：

```
设置 → 应用 → 默认应用 → 主屏幕应用 → 选择「虚拟屏桌面」
```

设成默认桌面后开机即进入本应用，配合悬浮球可以随时切换虚拟屏上的应用。

## 能否同时开多块虚拟屏

可以。`overlay_display_devices` 支持用逗号分隔多个规格，例如：

```bash
adb shell settings put global overlay_display_devices "720x1280/280,1280x720/280"
```

本项目界面当前只管理一块屏。多屏场景可以手动执行上面的命令，再用「虚拟屏」页的列表选中目标屏。

## 卸载后虚拟屏还在

虚拟屏配置是全局设置项，卸载应用不会自动清空。手动清掉：

```bash
adb shell settings put global overlay_display_devices ""
```

或者重启设备，虚拟屏是临时性的，重启即消失。
